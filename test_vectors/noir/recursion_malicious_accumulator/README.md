# recursion_malicious_accumulator — F1 soundness-gap regression fixtures

These fixtures pin the fix for the native-verifier soundness gap F1: the final
`UltraHonk::verify` pairing check must aggregate the public-input pairing-point
accumulator (the last `PAIRING_POINT_ACCUMULATOR_SIZE` public inputs) into the
Shplemini/PCS pairing points and check the AGGREGATE, mirroring bb's
`UltraVerifier::verify_proof`. A recursive circuit carrying a MALICIOUS
accumulator is accepted by a verifier that checks only the PCS points, but
rejected once the accumulator is aggregated in.

The outer proof is generated by the plain prover over the `recursion` circuit
(`../recursion`). The in-circuit recursive verifier is complete-but-not-sound:
it accepts arbitrary inner-proof bytes and emits the resulting pairing-point
accumulator into the outer public inputs, deferring soundness to this final
pairing check. So the outer proof is honestly generated over a garbage inner
proof — no prover/proof/VK tampering.

Files (poseidon2 transcript, non-ZK):
- `honest_proof` / `honest_public_inputs` — outer proof over the genuine inner
  proof from `../recursion/Prover.toml`. bb ACCEPTS; co-noir ACCEPTS.
- `malicious_proof` / `malicious_public_inputs` — outer proof over a TAMPERED
  inner proof (see `malicious_Prover.toml`). bb REJECTS at the pairing check;
  co-noir REJECTS post-fix, ACCEPTED pre-fix (the bug).
- `vk` — the recursion circuit's barretenberg-format VK (poseidon2). Identical
  for both proofs (same circuit); pinned independently by `recursion_vk_kat`.
- `malicious_Prover.toml` — the tampered inputs used to regenerate
  `malicious_proof` (the inner proof's KZG:W y-coordinate is negated).

## Regeneration

The tamper: take `../recursion/Prover.toml` and negate the y-coordinate of the
inner proof's final point (KZG:W = the last 4 proof limbs `[x_lo,x_hi,y_lo,y_hi]`,
136/118-bit split), giving `malicious_Prover.toml`.

```sh
# from repo root; the recursion prover needs a large stack under plaindriver
ulimit -s unlimited
cargo build --release --bin plaindriver
CRS_G1=co-noir/co-noir-common/src/crs/bn254_g1.dat
CRS_G2=co-noir/co-noir-common/src/crs/bn254_g2.dat
CIRC=test_vectors/noir/recursion/kat/recursion.json
DIR=test_vectors/noir/recursion_malicious_accumulator

# honest
target/release/plaindriver --prover-crs $CRS_G1 --verifier-crs $CRS_G2 \
  --input test_vectors/noir/recursion/Prover.toml --circuit $CIRC \
  --hasher poseidon2 --out-dir /tmp/honest
cp /tmp/honest/proof_plaindriver          $DIR/honest_proof
cp /tmp/honest/public_inputs_plaindriver  $DIR/honest_public_inputs
cp /tmp/honest/vk_plaindriver             $DIR/vk

# malicious
target/release/plaindriver --prover-crs $CRS_G1 --verifier-crs $CRS_G2 \
  --input $DIR/malicious_Prover.toml --circuit $CIRC \
  --hasher poseidon2 --out-dir /tmp/malicious
cp /tmp/malicious/proof_plaindriver          $DIR/malicious_proof
cp /tmp/malicious/public_inputs_plaindriver  $DIR/malicious_public_inputs
```

Referee with the bb oracle (versions.env BARRETENBERG_BINARY_DEFAULT): bb must
ACCEPT honest and REJECT malicious.

```sh
bb verify --scheme ultra_honk --oracle_hash poseidon2 --disable_zk \
  -p $DIR/honest_proof    -i $DIR/honest_public_inputs    -k $DIR/vk   # accepts
bb verify --scheme ultra_honk --oracle_hash poseidon2 --disable_zk \
  -p $DIR/malicious_proof -i $DIR/malicious_public_inputs -k $DIR/vk   # rejects
```

NOTE: recursion proof BYTES are prover-specific (the in-circuit verifier's
`mask_points` samples a random offset generator), so a regenerated proof will
not be byte-identical to the committed one — that is expected. The regression
criterion is accept/reject, not byte-equality; VK bytes are deterministic.
